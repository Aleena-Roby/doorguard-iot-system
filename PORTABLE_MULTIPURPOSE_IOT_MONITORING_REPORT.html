PORTABLE MULTIPURPOSE IOT-BASED MONITORING AND ALERT SYSTEM

1. INTRODUCTION

Monitoring the opening and closing of doors, windows, gates, cabinets, lockers and other access points is important in residential, commercial and industrial environments. These openings may sometimes be left open unintentionally, creating security risks, unauthorized access, safety concerns and other inconveniences.

Traditional monitoring systems are often designed for a specific location or application. For example, a conventional door monitoring system may be installed permanently on a particular door, making it less convenient to reuse in other locations.

To address this limitation, this project proposes a Portable Multipurpose IoT-Based Monitoring and Alert System. The system uses an ESP32 microcontroller and a magnetic reed switch to detect the opening and closing of different objects. The monitoring device can be relocated and installed at suitable locations, allowing the same device to serve multiple monitoring applications.

The ESP32 processes the sensor input and transmits the detected status through Wi-Fi to a backend system. The backend stores monitoring information in a database, while a web-based dashboard displays the current status and recorded events. This provides users with a convenient way to monitor different openings and view their activity.

The proposed system offers a reusable, flexible and cost-effective approach to IoT-based monitoring, with applications in homes, offices, storage areas and other environments.

2. AIM OF THE PROJECT

The main aim of this project is to design and develop a portable multipurpose IoT-based monitoring and alert system using an ESP32 microcontroller and a magnetic reed switch to detect opening and closing events in different locations. The system aims to transmit sensor data to a backend, store monitoring events in a database and display the current status through a web-based dashboard.

3. OBJECTIVES

  • To design a portable monitoring device using an ESP32 microcontroller and a magnetic reed switch.
  • To detect the opening and closing status of doors, windows, gates, cabinets and other suitable objects.
  • To transmit sensor data from the ESP32 to a backend system through Wi-Fi.
  • To develop a containerized backend for processing and managing sensor data.
  • To store device status and event history in a database.
  • To develop a web-based dashboard for displaying real-time monitoring information.
  • To provide a reusable and flexible monitoring solution that can be relocated and configured for different applications.

4. EXISTING SYSTEM

Existing door and access monitoring solutions typically rely on fixed mechanical locks, permanent hardwired alarm circuits, or single-location chimes attached immovably to a specific doorway or window frame.

Disadvantages:

  • Lack of Portability & Flexibility: Systems are permanently installed on one specific aperture; relocating them to an office locker, sliding window, or filing cabinet requires complex disassembly and rewiring.
  • No Remote Visibility: Traditional local buzzers sound only within close earshot; users receive zero indication of access events when in another room, floor, or outside the building.
  • Absence of Open-Duration Tracking: Conventional sensors cannot measure how long an object has remained open, failing to alert users when a locker or cleanroom cabinet is left ajar.
  • Silent Failure & Lack of Connection Monitoring: If power is disconnected or the device fails, traditional systems show no warning—they simply fail silently without indicating that the device is offline.
  • High Cost & Proprietary Lock-In: Commercial alarm setups impose proprietary hardware, complex installation fees, and recurring service subscriptions.

5. PROPOSED SYSTEM

The proposed system introduces a compact, portable, and multipurpose IoT monitoring unit built around an ESP32 microcontroller and a magnetic reed switch sensor. By utilizing the microcontroller's internal pull-up resistor (INPUT_PULLUP on GPIO 4), the physical sensor interfaces directly using a two-wire connection without requiring external resistors or bulky prototyping boards.

The device is physically modular and lightweight, enabling non-invasive surface mounting using adhesive pads or magnetic brackets. This design allows users to easily transfer the same device between doors, sliding windows, security lockers, and office cabinets. The ESP32 executes an optimized 50ms software debounce filter to verify mechanical contact states without false bouncing.

Upon state transition, the ESP32 transmits a JSON telemetry packet containing device ID, state (OPEN/CLOSED), and sequence number over 2.4 GHz Wi-Fi to a containerized backend. Crucially, the firmware dispatches periodic keep-alive heartbeats every 10–30 seconds. If the hardware is powered down or loses connection, the system detects the heartbeat timeout and alerts the user that the device is not connected, preventing misleading displays of outdated data.

6. SYSTEM ARCHITECTURE

The system architecture consists of two cohesive subsystems: the Portable Edge Sensing Unit and the Containerized Backend & Dashboard Service.

6.1 Hardware Components

  • ESP32 Microcontroller: Dual-core 32-bit Xtensa LX6 CPU (240 MHz) with integrated 2.4 GHz 802.11 b/g/n Wi-Fi, 520 KB SRAM, and hardware timers. Handles sensor debouncing, JSON serialization, and Wi-Fi transmission.
  • Magnetic Reed Switch (MC-38): Passive hermetically sealed dry-contact switch in durable ABS housing. Senses proximity of the actuator magnet within 15mm with zero mechanical friction.
  • Actuator Magnet: High-flux permanent neodymium magnet mounted on the movable door leaf, window sash, cabinet door, or locker lid.
  • Direct Jumper Wires: Two direct low-resistance wire leads connecting the reed switch directly to ESP32 GPIO 4 and GND with minimal footprint.
  • 5V DC Power Source: Powered via a standard 5V Micro-USB or portable 5V power bank, ensuring seamless mobility and rapid redeployment.
  • Onboard Diagnostic LED (GPIO 2): Visual status indicator (steady pulse when open, solid on when secured, blink pattern when disconnected).

6.2 Software Components

  • ESP32 C/C++ Firmware: Non-blocking embedded firmware incorporating WiFiMulti, HTTPClient, and ArduinoJson. Manages 50ms software debounce filtering, periodic heartbeat pinging, and automatic Wi-Fi reconnection.
  • Containerized Python Flask Backend: Modular Flask REST API running in Docker containers via Gunicorn WSGI. Manages endpoint routing (/api/events, /api/status, /api/devices), device heartbeat tracking, and analytics computation.
  • PostgreSQL Database: PostgreSQL 16 container with persistent named volume storage, guaranteeing ACID-compliant transaction safety for device states, heartbeat logs, and timestamped audit records.
  • Docker & Docker Compose: Multi-service containerization isolating backend API and database services, ensuring consistent local and cloud deployments.
  • React Web Dashboard: High-performance single-page application built with React, TypeScript, Vite, and Tailwind CSS. Provides real-time status visualizations, multipurpose device switching, and activity charts.
  • Web Audio Warning Siren: Synthesizes audible alarm sirens natively within the web browser upon exceeding a user-defined open-duration threshold.

7. WORKING PRINCIPLE

  1. Modular Physical Mounting: The reed switch is mounted to a stationary frame (door jamb, window frame, or locker rim), and the magnet is attached to the movable section (< 15mm gap).
  2. Contact Sensing & Debouncing: Contact closure pulls GPIO 4 to LOW (GND, CLOSED state); separation allows the internal pull-up to pull GPIO 4 to HIGH (3.3V, OPEN state). A 50ms software filter confirms true transitions.
  3. Microcontroller Processing: The ESP32 detects the transition, increments an internal sequence number, and packages the event into a JSON payload.
  4. Wi-Fi Telemetry & Heartbeat: The ESP32 sends an HTTP POST request to the containerized backend over Wi-Fi. In parallel, it transmits keep-alive heartbeats every 10–30 seconds.
  5. Backend Ingestion & Storage: The Flask backend validates the payload, updates device records, and commits a timestamped entry to the PostgreSQL database.
  6. Real-Time Visualization & Alerting: The web dashboard displays current status, runs open-duration timers, sounds an audible siren if an opening is left ajar, and alerts the user if device heartbeats cease.

9. CONTAINERIZED BACKEND & DATABASE HOSTING

The backend architecture uses Docker containerization to deliver a reliable, isolated, and scalable environment for telemetry ingestion and data storage:

  • Multi-Container Architecture: Managed via Docker Compose, decoupling the Python Flask REST API service (doorguard-backend) from the PostgreSQL database engine (doorguard-postgres).
  • PostgreSQL 16 Alpine Database: Utilizes lightweight Alpine Linux container images with dedicated persistent volume mounts (postgres_data) to ensure complete audit history retention across system restarts.
  • Automated Health Checks: Implements container health checks (pg_isready) to ensure the Flask API service only connects once the database is fully operational.
  • RESTful Telemetry Endpoints: Exposes structured REST endpoints (/api/events, /api/status, /api/devices, /api/stats) with CORS support for seamless web integration.
  • Heartbeat Timeout Detection: Actively checks incoming device heartbeat intervals against a configurable threshold (30s), flagging unpowered or disconnected units immediately.
  • Cloud & Local Portability: The standardized container definition runs identically in local development or deployed on cloud container platforms without code modifications.

10. RESULTS

The portable multipurpose monitoring prototype was fabricated and tested across multiple residential and storage environments. Key empirical results include:

  • Multipurpose Validation: Successfully mounted and verified across a room door, a sliding balcony window, and an office storage locker with zero wiring alterations.
  • Low-Latency Transmission: End-to-end event delivery from physical magnetic contact to backend ingestion achieved in 180ms to 350ms over standard Wi-Fi.
  • 100% Debounce Accuracy: The 50ms software debounce algorithm completely eliminated contact flutter and mechanical vibrations during rapid openings and closures.
  • Proactive Disconnection Detection: When the ESP32 was disconnected from power or Wi-Fi, the backend accurately flagged the device as offline within 30 seconds, presenting a "Device Not Connected" notice on the dashboard.
  • Reliable Audit History: Recorded 1,000 continuous opening and closing events into PostgreSQL with zero lost records or sequence gaps.

11. ADVANTAGES

  • Portability & Reusability: Compact, modular design allows one unit to be reused across doors, windows, gates, cabinets, and lockers.
  • Minimalist Hardware: Employs internal pull-up resistors; eliminates discrete external resistors and complex wiring.
  • Connection Awareness: Periodic heartbeats prevent silent failures, immediately notifying users if the device is disconnected or unpowered.
  • Containerized Reliability: Dockerized environment guarantees consistent, reproducible deployments and persistent data integrity.
  • Cost-Effective Architecture: Built using affordable, accessible open hardware components with zero proprietary subscription fees.

12. APPLICATIONS

  • Residential Security: Monitoring entrance doors, balcony sliders, kitchen windows, and perimeter gates.
  • Commercial & Personal Storage: Securing gym lockers, office filing cabinets, and confidential document drawers.
  • Retail & Showrooms: Protecting glass jewelry showcases, high-value electronics display cases, and cashier storage.
  • Industrial & Healthcare: Monitoring pharmaceutical cleanroom cabinets, hazardous chemical storage, and machinery safety covers.

  • Battery Optimization & Deep Sleep: Utilizing external GPIO wake interrupts on the ESP32 to achieve multi-month battery life on rechargeable Li-ion cells.

  • Push Notification Service: Integrating Web Push notifications and Telegram bot alerts to deliver mobile phone notifications when access points remain open.
  • Custom 3D-Printed Enclosure: Fabricating a compact, weather-resistant snap-fit enclosure with integrated magnetic mounting brackets for rapid relocation.
  • Machine Learning Activity Analytics: Analyzing temporal opening patterns to automatically detect anomalous or unauthorized access outside normal hours.

14. CONCLUSION

The Portable Multipurpose IoT-Based Monitoring and Alert System successfully addresses the rigidity and limitations of conventional, single-location monitoring systems. By interfacing an ESP32 microcontroller with a magnetic reed switch using internal pull-up logic, the system achieves a compact, reliable, and reusable monitoring unit that can be easily relocated across doors, windows, cabinets, and lockers without complex or cumbersome wiring.

The containerized Python Flask backend and PostgreSQL database ensure robust data processing, persistent audit logging, and automated device disconnection detection through keep-alive heartbeats. Coupled with an intuitive, responsive React dashboard featuring real-time status display and audible siren warnings, the project delivers a cost-effective, scalable, and versatile IoT security solution well-suited for residential, commercial, and industrial environments.

15. PROJECT DESIGN

Data Flow:

  1. Physical State Detection: Movement of door, window, or locker separates/unites magnet and reed switch; contacts open or close.
  2. Edge Debouncing & Logic: ESP32 samples GPIO 4 with internal INPUT_PULLUP; a 50ms software filter confirms clean state transition.
  3. Wi-Fi Telemetry Dispatch: ESP32 transmits JSON payload (state, sequence number, device ID) to containerized backend via HTTP POST.
  4. Containerized Ingestion & Storage: Flask backend validates payload, updates heartbeat timestamp, and writes audit record to PostgreSQL.
  5. Dashboard Presentation & Alert: React dashboard renders live state, runs duration timer, sounds siren if threshold is exceeded, or displays "Device Not Connected" if heartbeats cease.
